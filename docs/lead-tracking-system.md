# Lead tracking system — как искать, вести и считать клиентов

Операционная система продаж для suslicketeam на старте: **как находить бизнесы,
вести каждого лида от первого касания до сделки в одном месте, и получать наглядную
статистику — бесплатно, без отдельной CRM.**

Связанные доки: `outreach-playbook.md` (тексты исходящих сообщений + каденс),
`whatsapp-messages.md` (входящие), `utm-links.md` (UTM-ссылки для атрибуции).

---

## Главный принцип

**Не строй CRM для клиентов, которых ещё нет.** На нуле лидов 80% энергии — в
привлечение (стадия 1), а учёт должен быть настолько простым, чтобы вести его было
не лень. Красивая статистика появляется «бесплатно» — сама, из правильно устроенного
листа, — когда накопятся данные. Свой кастомный CRM на сайте — это **кейс для
портфолио на потом** (2–3 месяца), когда процесс докажет себя на реальных данных.

Приоритеты:
1. **Привлечение** — поток разговоров (холодный аутрич по 2GIS + входящие с сайта).
2. **Учёт** — один лист, одна строка на компанию, фиксированные статусы.
3. **Статистика** — считается формулами из того же листа, отдельной системы не нужно.

## 1. Воронка лида (общая модель)

```
[1] ИСТОЧНИК          [2] КОНТАКТ            [3] СДЕЛКА              [4] АНАЛИТИКА
найти/привлечь   →    лид ответил      →    ведём по статусам  →   считаем итоги
2GIS (холодный)       reply             qualified → КП → won     воронка, каналы,
сайт CTA + UTM        (он написал)      / lost                   ниши, выручка
QR-футболка
```

Ключевая идея: **при холодном аутриче воронка начинается ДО лида.** Сначала есть
«компания, которой я ещё не написал» (проспект) — и только когда она ответила, это
лид. В нашей таблице проспект — это просто самая ранняя стадия (`надо написать`),
поэтому всё живёт в одном листе.

Вторая идея: каждый лид таскает за собой **источник/UTM**. Входящие с сайта уже несут
first-touch UTM (`sl_utm` → префилл в мессенджер). Вписываешь её в колонку `Источник` —
и одна таблица меряет и холодный, и входящий поток в одних единицах.

## 2. Структура листа (источник правды)

Один лист `Leads`, одна строка на компанию. Колонки:

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | число | автонумерация (порядковый) |
| `Дата добавления` | дата | когда нашёл / когда написал |
| `Компания` | текст | название |
| `Ниша` | enum | салон / стома / кафе / автосервис / юрист … (для статистики «что заходит») |
| `Город` | текст | Алматы / др. |
| `Контакт` | текст | WhatsApp / Instagram / телефон |
| `Ссылка` | URL | карточка 2GIS / Instagram / их сайт |
| `Есть сайт?` | enum | `нет` / `слабый` / `есть` — главный квалификатор (ICP-фильтр) |
| `Источник` | enum | `2gis` / `site` / `instagram` / `referral` / `event` / `shirt` |
| **`Статус`** | enum | воронка (см. ниже) |
| **`Следующий шаг`** | текст | что сделать дальше |
| **`Дата след. шага`** | дата | когда (твой «будильник») |
| `Сумма` | число | бюджет сделки (если `won`) |
| `Причина отказа` | enum | `нет ответа` / `дорого` / `есть сайт` / `не сейчас` / `другое` |
| `Заметки` | текст | контекст, история |

Жирным — **три операционные колонки, которые двигают сделки**: `Статус`,
`Следующий шаг`, `Дата след. шага`.

### Значения `Статус` (enum — это важно)

```
надо написать  →  написал  →  ответил  →  квалифицирован  →  КП  →  выиграл
                                                                  ↘  слил
```

| Статус | Что значит | Условие перехода |
|---|---|---|
| `надо написать` | проспект найден, ещё не контактировал | добавил из 2GIS |
| `написал` | отправил первое касание | → ставь дату след. шага +3 дня |
| `ответил` | он откликнулся | живой диалог начался |
| `квалифицирован` | целевой, есть задача и бюджет | прошёл `/бриф` |
| `КП` | отправил предложение/цену | ждём решение |
| `выиграл` | сделка состоялась | заполни `Сумма` |
| `слил` | отказ / тишина после 4 касаний | заполни `Причина отказа` |

> **Почему enum, а не свободный текст.** Фиксированный список (через «Проверку
> данных» в Google Sheets) → статистика считается одной формулой `COUNTIF`. «думает»,
> «ну почти», «перезвонит» — убивают аналитику и прячут реальный статус.

CSV-шаблон с готовыми колонками и примером строки: `lead-tracker-template.csv`
(импортируй в Google Sheets → «Файл → Импорт»).

## 3. Чем вести — выбор инструмента (бесплатно / self-hosted)

| Инструмент | Тип | Плюсы | Минусы | Кому |
|---|---|---|---|---|
| **Google Sheets** ⭐ | облако, free | QR-опрос уже пишет в Sheets → один источник правды; графики и сводные встроены; делается за час | не «продукт» | **старт, прямо сейчас** |
| Notion | облако, free | красивые карточки-канбан, мобильное приложение | статистику сложнее считать; ещё один сервис | если важнее визуал карточек |
| Trello | облако, free | чистый канбан по статусам, drag-and-drop | слабая аналитика | если мыслишь досками |
| **NocoDB** | self-host, OSS | Airtable у себя; БД + формы + API; ставится на VPS/Docker | надо хостить | когда перерастёшь Sheets |
| **Twenty** | self-host, OSS | современный open-source CRM (альтернатива Salesforce) | тяжелее, надо хостить | при потоке десятки/нед |
| EspoCRM / Odoo CRM | self-host, OSS | классический полноценный CRM | избыточно на старте | позже, с командой |
| **Свой мини-CRM на сайте** | твой стек | полный контроль; **кейс в портфолио**; на Cloudflare **D1** (SQLite, free-tier) ложится идеально | недели работы | **через 2–3 мес**, на реальных данных |

**Рекомендация:** Google Sheets сейчас. Тот же лист → источник для дашборда → позже
переносишь данные в свой мини-CRM на Cloudflare D1 как живой кейс «студия, которая
автоматизировала свой sales». Строить его сейчас, на пустых данных, — прокрастинация
под видом продуктивности (YAGNI).

## 4. Где искать бизнесы (методы) + «карта бизнесов»

### Источники проспектов

| Источник | Что даёт | Как квалифицировать |
|---|---|---|
| **2GIS** ⭐ | каталог локального бизнеса Алматы с контактами, отзывами, наличием сайта | главный канал — см. ниже |
| Yandex Карты / Бизнес | то же + кто уже в Яндексе (а кто нет) | «нет в Яндексе» = боль для питча |
| Google Maps | бизнесы с отзывами, но часто без сайта | «отзывы есть, сайта нет» = горячо |
| Instagram (по гео/хэштегам) | активный бизнес, вкладывающийся в маркетинг | есть IG, нет сайта = `+1 канал` оффер |

### Квалификация в 2GIS (заполняет `Есть сайт?` + `Ниша`)

Ты ищешь **не «бизнес», а бизнес, которому сайт принесёт деньги и у которого деньги
есть**. Два фильтра:

1. **Ниша, где сайт влияет на выручку:** стома/клиники, бьюти/салоны, фитнес,
   автосервисы/детейлинг, кафе/доставка, ремонт/дизайн, юристы/консультанты, ивенты.
   Слабо: продуктовые, госуслуги, монополии. **Бери одну нишу за раз** — оттачиваешь
   один питч и видишь, какая конвертит.
2. **Сигнал готовности платить:**

| Что видишь в карточке | Оценка | Действие |
|---|---|---|
| Сайта нет, но 100+ отзывов | 🔥 топ | пишешь первым |
| Есть Instagram, сайта нет | 🔥 уже платит за маркетинг | пишешь |
| Сайт на Tilda / тормозит / не открывается на телефоне | ✅ хороший | оффер «переделать» |
| Платное продвижение в 2GIS | ✅ есть бюджет | приоритет |
| Свежий нормальный сайт | ⛔ скип | не трать время |

**Зацепка под каждого** (это весь секрет холодного аутрича): найди один конкретный
факт — «300 отзывов, но в Google вас нет», «сайт не открывается на телефоне». Тексты
под это — в `outreach-playbook.md` (Method 2 + по-нишевые шаблоны).

### «Карта бизнесов» — два смысла

1. **База (главная карта).** Сам лист `Leads` и есть карта: фильтруешь по `Ниша`,
   `Город`, `Статус`, `Есть сайт?` — видишь, где ты по каждому.
2. **Литеральная гео-карта (бесплатно, наглядно).** Импортируй лист в **Google My
   Maps** → проспекты пинами на карте Алматы, цвет пина = `Статус`. Видно, какие
   районы/кластеры отработаны. Обновляется из того же листа.

> **Не строй скрапер 2GIS сейчас.** На 10–20 проспектов в день руками быстрее, и ты
> читаешь карточку глазами — это и есть квалификация. Скрапер окупится после ~сотни
> контактов/день, не раньше (YAGNI).

## 5. Ритм ведения — чтобы лиды не протухали

**Железное правило:** ни одна активная строка не остаётся без `Следующего шага` и
`Даты`. Нет шага — статус `слил`. Третьего не дано. Это убирает главную утечку —
лиды «ответил, но не сейчас», которые тихо забываются.

### Ежедневный цикл (20–30 мин)

1. **Догон.** Фильтр: `Дата след. шага ≤ сегодня` → список на сегодня. Прошёлся,
   написал, проставил новую дату.
2. **Новые.** Добавил 10–15 проспектов из 2GIS, написал первое касание, статус →
   `написал`, дата след. шага → +3 дня.
3. Всё. Закрыл таблицу.

### Каденс follow-up (холодному не отвечают с первого раза — норма)

| Касание | Когда | Смысл |
|---|---|---|
| #1 первое | День 0 | зацепка + мини-аудит |
| #2 догон | День +3 | «глянули? вот пример из вашей ниши» |
| #3 догон | День +7 | другой угол: цифра/кейс/выгода |
| #4 финал | День +14 | «закрываю, но оставлю аудит» |
| → `слил` | после #4 | причина = `нет ответа`; вернуться через 3 мес |

Половина ответов — на касании #2–#3. Готовые тексты #1–#4 (RU/KK/EN) — в
`outreach-playbook.md`. `слил` ≠ «удалить»: холодный «нет» часто = «не сейчас», строка
остаётся как тёплый пул на будущее (реактивация через сезон/акцию).

> **Ограничь WIP.** Не добавляй 200 проспектов, если успеваешь догонять 30. Лучше 30
> доведённых до ответа, чем 200 брошенных после первого касания.

## 6. Статистика «бесплатно» — лист становится дашбордом

Раз `Статус`, `Источник`, `Ниша`, `Сумма` — enum/число, аналитика считается формулами
на втором листе `Дашборд`. Пересчитывается сам.

**1. Воронка (главная картинка)** — `COUNTIF` по статусам:
```
написал      120  ──────────────
ответил       28  ────        (reply rate 23%)
квалиф.       12  ──          (45% от ответов)
КП             6  ─
выиграл        3              (win 50% от КП; 2.5% от написал)
```
Видно, где течёт: низкий reply rate → плохой первый месседж; ответы есть, но не доходят
до КП → слабая квалификация.

**2. Каналы** (сводная по `Источник`): где конверсия в сделку выше и где дешевле лид.
**3. Ниши** (сводная по `Ниша`): по какой нише бить дальше.
**4. Прогноз выручки:** `Сумма` × вероятность стадии (КП ~40%, квалиф ~20%) =
ожидаемый доход в работе; `SUM` по `выиграл` = факт.

Всё это — встроенные «Сводные таблицы» + «Диаграммы» Google Sheets, **ноль кода**.

> **На нуле данных смотри только 2 метрики:** сколько написал (активность — в твоих
> руках) и **reply rate** (работает ли питч). Конверсия в сделку и выручка
> статистически бессмысленны, пока сделок единицы — не обманывайся ранними процентами.
> **Дашборд читается за 10 секунд или он не нужен:** один экран — воронка + 3 цифры
> недели (написал / ответил / в работе).

## 7. Roadmap (по фазам, без преждевременной сложности)

| Фаза | Когда | Что делаешь |
|---|---|---|
| **0. Сейчас** | неделя 1 | Импорт CSV в Google Sheets; добавить «Проверку данных» на enum-колонки; начать ежедневный цикл (Раздел 5) |
| **1. Поток** | недели 1–4 | 10–20 проспектов/день по одной нише; цель — найти заходящий питч (метрика: reply rate) |
| **2. Дашборд** | когда ~50+ строк | второй лист со сводными + диаграмма воронки; (опц.) Google My Maps |
| **3. Self-host** | поток десятки/нед | перенос в NocoDB/Twenty или **свой мини-CRM на Cloudflare D1** — кейс в портфолио |
