# suslicketeam — дизайн сайта-портфолио

**Дата:** 2026-06-08
**Статус:** дизайн утверждён, готов к плану реализации

## 1. Цель и позиционирование

Продающий сайт-портфолио веб-разработчика/мини-студии, ориентированный на бизнес в
Казахстане. Главная задача — превратить посетителя в диалог в мессенджере.

- **Главный CTA:** написать в WhatsApp (основной) / Telegram. Клик отслеживается как
  конверсия.
- **Позиционирование:** гибрид. Бренд команды **suslicketeam** на витрине, основатель —
  лицо и точка контакта (личное доверие закрывает сделку).
- **Услуги (полный цикл, отдельная посадочная под каждую):** лендинги/сайты-визитки,
  веб-приложения и SaaS, AI-интеграции/AI-продукты, мобильные приложения, SEO/оптимизация.
- **Целевой клиент:** малый и средний бизнес КЗ; вторично — англоязычные международные.

## 2. Технологический стек

| Слой | Выбор | Обоснование |
|------|-------|-------------|
| Фреймворк | Next.js 15 (App Router) + TypeScript | SSG/ISR, лучший SEO, экосистема |
| Стили | Tailwind CSS + shadcn/ui | Скорость разработки, консистентность |
| i18n | next-intl | Типобезопасные переводы, корректный hreflang в App Router |
| Темы | next-themes | Тёмная/светлая без FOUC |
| Анимации | Framer Motion + Canvas/WebGL | Premium-ощущение |
| Формы | React Hook Form + Zod | Типобезопасная валидация |
| Хостинг | Cloudflare через `@opennextjs/cloudflare` | PoP ближе к КЗ, дешевле, SSR/ISR |

**Рендеринг:** почти весь сайт — статика (SSG) с ревалидацией ради максимальных Core Web
Vitals. Динамика (форма, трекинг) — клиент + Cloudflare-функция.

## 3. Структура страниц и i18n

Языки: **русский + казахский (равные в SEO) + английский**. `localePrefix: 'always'` —
явные префиксы `/ru`, `/kk`, `/en` у всех. Корень `/` редиректит по `Accept-Language`/гео.

```
/{locale}                      Главная
/{locale}/services             Обзор услуг
/{locale}/services/landing     Лендинги и сайты-визитки
/{locale}/services/web-apps    Веб-приложения и SaaS
/{locale}/services/ai          AI-интеграции и AI-продукты
/{locale}/services/mobile      Мобильные приложения
/{locale}/services/seo         SEO и оптимизация
/{locale}/cases                Портфолио (сетка)
/{locale}/cases/[slug]         Детальный кейс
/{locale}/about                Обо мне и команде
/{locale}/contact              Контакты + форма
```

**Контент** — структурированные файлы (MDX/JSON), один файл на кейс × язык. Без CMS на
старте (YAGNI); архитектура позволяет добавить headless CMS позже. **Блог — позже**, не в
MVP.

## 4. SEO-фундамент

SEO — слой архитектуры, не плагин.

- Метаданные через `generateMetadata` — уникальные title/description на страницу × язык.
- **hreflang** для всех локалей + `x-default`.
- `app/sitemap.ts` (все локали), `app/robots.ts`.
- **JSON-LD:** Organization, LocalBusiness (KZ-гео), Person, WebSite+SearchAction,
  Service (на услугах), BreadcrumbList, FAQPage.
- Open Graph / Twitter Cards + динамические OG-картинки (`next/og`) — важно для превью в
  WhatsApp/Telegram.
- Canonical на каждой странице.
- **Core Web Vitals:** `next/font` (без CLS), `next/image` (AVIF/WebP, lazy), минимум JS на
  статике. Цель Lighthouse 95–100, контроль через Lighthouse CI.
- **Локальное SEO КЗ:** LocalBusiness + Google Business Profile позже.

## 5. Аналитика, UTM и трекинг конверсий

**Стек:** GA4 (привлечение/UTM) + PostHog (поведение, session replay, воронки, heatmaps,
A/B) + Cloudflare Web Analytics (CWV, без cookie). Все через `next/script`
`afterInteractive`, не вредят CWV.

- **PostHogProvider** инициализируется в клиентском компоненте; `$pageview` шлётся **вручную
  при смене маршрута** (usePathname/useSearchParams) — обязательно для SPA-навигации.
- **Единый модуль `analytics.ts`:** `trackEvent(name, params)` шлёт в GA4 + PostHog разом.
- **UTM сквозным слоем:** при заходе с метками — сохраняем в sessionStorage, прокидываем в
  события и **вшиваем в текст первого сообщения мессенджера** (страница-источник + кампания).
- **Конверсия = клик в мессенджер:** событие `lead_messenger_click` (GA4 generate_lead как
  конверсия + PostHog capture).
- Доп. события: сабмит формы, смена языка/темы, глубина скролла, клики по кейсам.
- **Consent:** лёгкий cookie-баннер для GA4/PostHog; Cloudflare — без cookie.
- Серверный трекинг (Measurement Protocol) — позже, при росте трафика.

## 6. Дизайн и UX

**Стиль:** тёмная премиальная тема + переключатель (демонстрация навыка). Контраст ≥ 4.5:1
(WCAG AA). Без FOUC через inline-скрипт темы в `<head>`.

**Hero — живая витрина навыка (комбо, поэтапно):**
- Слой 1 (сейчас): интерактивная **constellation на Canvas 2D** — узлы/линии, реакция на
  курсор.
- Слой 2 (позже): **WebGL mesh-градиент**. Слои — независимые компоненты.
- **Защита скорости:** текст+кнопки = LCP, рендерятся мгновенно; фон монтируется лениво
  после гидратации. Уважаем `prefers-reduced-motion` (статика), пауза по
  IntersectionObserver вне экрана, упрощение на слабых устройствах (hardwareConcurrency,
  deviceMemory).

**Структура главной (по психологии продаж):**
1. Hero — оффер + 2 CTA (WhatsApp/Telegram) + смена темы/языка
2. Логотипы/превью проектов (соц. доказательство)
3. Услуги — 6 карточек → посадочные
4. Кейсы — 3–4 лучших с метриками (задача→решение→результат)
5. Процесс — 4–5 шагов
6. Почему мы — выгоды
7. Отзывы (заглушки → заменить реальными)
8. FAQ + FAQPage JSON-LD
9. CTA-секция + форма-дубль + мессенджеры
10. Футер — контакты, языки, ссылки, реквизиты

**Sticky-кнопка мессенджера** на мобильных (главный CTA всегда под рукой).
**Анимации:** тонкий fade/slide на скролле, hover на карточках — без вреда CWV.

## 7. Приём заявок (CRM-агностик)

```
Форма → Cloudflare-функция (единый webhook) ─┬─→ Telegram-бот (заявка с UTM) [старт]
                                             ├─→ Google Sheets/Notion (мини-CRM) [старт]
                                             └─→ Bitrix24/amoCRM/HubSpot [позже, без переделки]
```

- **wa.me/t.me click-to-chat не пишет в CRM** — это намерение, ловим в аналитике. Реальная
  заявка из формы летит в webhook.
- Старт: Telegram-бот + таблица (бесплатно, мгновенно, видно источник каждого лида).
- Рост: полноценная CRM через тот же webhook + опционально WhatsApp Business API (radist/
  Wati/360dialog), чтобы чаты сами падали в CRM.
- **Форма:** имя, контакт, тип проекта (select), сообщение. Honeypot + rate-limit (без
  капчи). Оптимистичный UI, понятные ошибки, retry.

## 8. Тестирование и качество

- **Unit (Vitest):** UTM-парсер, сборка ссылок мессенджера, формат событий, валидация формы.
- **E2E (Playwright):** смена языка, смена темы (без FOUC), CTA → корректный wa.me/t.me URL с
  UTM, сабмит формы.
- **Lighthouse CI:** порог Performance/SEO/Accessibility ≥ 95 в CI.
- Локализованные `not-found.tsx` и `error.tsx` в фирменном стиле.
